# 课程方案：用 Spring Boot 开一家「南坡小炒」（学生版）

> 二十次课，你将从一行"本店开业"的标语开始，把成都理工大学工程技术学院南坡的这家小炒店，做成一个有数据库、有登录、有 AI 服务员、能一条命令部署的完整系统。
> 技术栈：Spring Boot 4.1.1 + JDK 17 + MySQL/H2 + Spring AI

---

## 一、这门课怎么玩

**一个项目贯穿到底。** 每一课都在上一课的代码上继续改，你的店一课一变样：

```
开业招牌(1) → 能点菜的网页(2) → 招人分工(3-4) → 店规统一(5-6)
→ 建账本：数据库(7-12) → 菜品照片与会员卡(13-16) → AI 服务员(17-18) → 连锁开店(19-20)
```

**三条学习规矩：**

1. **每课必须"验证全过 + git 提交 + 打 tag"才算下课**——期末你的 git 历史就是你的成绩单。
2. **不要提前优化。** 有些课会故意留下不规范的代码（比如写死在代码里的菜单、直接抛出的异常），它们是后面课程要亲手重构的伏笔。手册说"别修"就别修——在错误的时机追求完美，反而学不到"为什么要那样改"。
3. **报错先看日志。** 从上往下找第一行 ERROR，把异常名复制去搜索——这是工程师的基本功，本课程的坑都设计成"日志里能找到答案"。

## 三、每课详情

### 第 1 课 · 把店面立起来
从空目录建出 Spring Boot 项目：看懂 pom.xml（parent、starter——注意 Boot 4 已把 `starter-web` 改名 `starter-webmvc`）、启动类三合一注解、application.yml；写出第一个接口 `GET /hello`。
**悬念**：店开了，顾客却连菜单都看不到。

### 第 2 课 · 服务员接第一单
`@GetMapping/@PostMapping/@RequestBody`，JSON 与 Java 对象自动互转；服务员一个人包揽背菜谱、验菜、算账、炒菜；再写一个 fetch 网页，亲眼看到前后端配合。
**悬念**：服务员忙得脚不沾地——该招人了。

### 第 3 课 · 招入墩子和厨师
单一职责与分层：新建 service 包，墩子配菜、厨师炒菜，形成"服务员→墩子→厨师"调用链。这课你会**删掉**上节课的旧代码——改代码和写代码一样重要。
**悬念**：员工是服务员自己 new 出来的——谁来管人事？

### 第 4 课 · 员工由总部委派
IoC 与依赖注入：`@Service` 把类交给容器，`@Autowired` 让容器把员工"派"到你面前。启动日志会证明：员工在开店前就报到上岗了。
**悬念**：人事顺了，可小票格式五花八门，前端没法写。

### 第 5 课 · 全店统一小票
`Result<T>` 泛型封装（code/msg/data）+ 错误码字典。后端改了返回格式，前端必须同步适配——你会亲历"契约一变、两端联动"。
**悬念**：正常返回统一了，可点错菜还是喷一屏 500。

### 第 6 课 · 统一客诉处理
`@RestControllerAdvice` + `@ExceptionHandler`：业务异常与系统异常分流，访问不存在的路径也不再被误报成"服务器错误"。
**悬念**：菜谱写死在代码里，改个价格就要重新发版——该建账本了。

### 第 7 课 · 认识账本
H2 内存数据库、数据源四要素、ddl-auto、h2-console 可视化。还会见识 Spring Boot 4 的一个经典坑：H2 控制台被拆成了独立模块，不引入就永远 404。
**悬念**：账本是空的——菜单怎么变成表？

### 第 8 课 · 菜单上账
`@Entity/@Table/@Id/@Column` 实体、`JpaRepository` 零 SQL 查询、启动时自动初始化菜单数据。写死在代码里的菜谱从此消失。
**悬念**：订单还是"打完小票就扔"。

### 第 9 课 · 订单落库
一对多关联：`t_order`/`t_order_item`（为什么表名不能叫 order？）、级联保存、价格快照。下单业务整体搬进 OrderService，服务员彻底瘦身。
**悬念**：把订单实体直接返回给前端试试——JSON 当场爆炸。

### 第 10 课 · 小票与账本分离
实体为什么不能出库（循环引用、懒加载、字段泄露）；dto 入参、vo 出参、entity 账本，三层对象各司其职。
**悬念**：配菜配到一半失败，账本里会不会留半条订单？

### 第 11 课 · 要么全成，要么全不成
`@Transactional`：厨房着火（可开关模拟），整单回滚。有事务和没事务的对照实验，做完一辈子记得住。
**悬念**：订单多了，账本一页页翻不动。

### 第 12 课 · 翻账本
`Pageable` 分页、`Sort` 排序、`@Query` JPQL 联表查询"谁点过回锅肉"。
**悬念**：菜单全是文字，不诱人。

### 第 13 课 · 菜品拍照上架
`MultipartFile` 文件上传、类型与空文件校验、UUID 防重名、`StorageService` 接口 + 本地实现。
**悬念**：照片传上去了，浏览器怎么看到？

### 第 14 课 · 照片上墙
静态资源映射 `/files/**`、下载接口（Content-Disposition）、上传大小限制接入统一异常、防路径穿越。
**悬念**：网页人人能访问——谁知道是谁在下单？

### 第 15 课 · 办会员卡
`User` 表、BCrypt 加密存密码（为什么不能存明文）、JWT 三段结构、登录签发令牌。
**悬念**：卡发出去了，谁来查票？

### 第 16 课 · 查票与续卡
拦截器统一校验令牌、ThreadLocal 传递当前用户、长短令牌（15 分钟短卡 + 7 天长卡续期）、订单从此记名。
**悬念**：老板想招个 AI 服务员。

### 第 17 课 · AI 服务员上岗
Spring AI 接入大模型（OpenAI 兼容端点，换模型只改配置）、系统提示词、API Key 用环境变量管理。
**悬念**：AI 只会聊天，怎么真下单？

### 第 18 课 · AI 会下单
结构化输出：把"来份不辣的下饭菜"变成订单对象，直接调用你的 OrderService——业务代码一行不改；工具调用：让 AI 查你的真实菜单。
**悬念**：店要开到任何机器上。

### 第 19 课 · 连锁开店
Docker 多阶段构建、docker-compose 编排 app + MySQL + MinIO；改几个环境变量完成 H2→MySQL、本地磁盘→MinIO 的切换——配置外部化的总验收。
**悬念**：隔壁餐厅让 AI 客户端直接点菜？

### 第 20 课 · 新框架巡礼与结课
MCP（把你的店变成 AI 可调用的工具服务器，现场彩蛋）、Spring gRPC、Spring Modulith 一览；回顾二十课演进，规划后续学习路线。

## 四、每课的学习节奏

每课的文件夹里固定三个文件：`01-课程导入`（先读，进入状态）→ `02-动手做`（跟着做，代码可直接抄）→ `03-验证提交练习`（验证全过 + 提交打 tag + 课后练习）。

遇到问题按顺序自救：看手册的"常见报错"表 → 看启动日志第一行 ERROR → 搜索异常信息 → 课堂提问。
